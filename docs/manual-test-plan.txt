--------------------------------------------------------------------------------
0. HOW TO USE THIS PLAN
--------------------------------------------------------------------------------

Sections 1-3 are setup. Read them once.

Section 4 defines eight named configurations (CFG-A .. CFG-H). Almost every
later test says "start a run on CFG-x", which means: set the options exactly as
listed in section 4, then NEW GAME.

Sections 5-15 are the test suites. Each test has an ID, a setup, numbered
steps, and expected results. Record PASS / FAIL / BLOCKED per ID using the
template in section 17.

Priority markers:
  [P0] Release blocker. Run every time.
  [P1] Core correctness. Run before any release.
  [P2] Run when the related area changed.
  [P3] Nice to have / long-tail.

WHAT NOT TO TEST HERE
The automated suite already covers determinism vectors, RNG bounds, one-to-one
uniqueness, level bounds, legendary filters, save schema validation, script
label control flow, and package layout. Do not spend manual time re-deriving
those. Manual testing exists to check the things Lua tests cannot see: what the
player actually sees on screen, whether dialogue matches the awarded Pokemon,
whether one-time events stay consistent, and whether the engine seams behave.

1.4 Baseline artifacts to capture before you start

  Keep a scratch folder per test session containing:

    - the exported spoiler .txt for each run

  You will diff these constantly. Most failures in this mod present as "two
  things that should agree, don't", and you need both halves to prove it.

1.5 Seeing the mod's log output  (DO THIS BEFORE ANY TEST THAT EXPECTS A LOG LINE)

  The mod reports through mod.log:info / :warn / :error, which the engine
  renders as attributed "[pokemon_randomizer] ..." lines. The engine docs do
  not state where those lines are delivered, so establish that for your build
  ONCE, at the start of a session, and write it in your notes.

  Candidate destinations, in the order worth checking:
    (a) stdout / stderr - launch the game from a terminal rather than by
        double-clicking:
            love .                      (from the engine repo root)
            love "path\to\game"         (packaged build)
        On Windows use a console that keeps output, e.g. run it from
        PowerShell and do not close the window.
    (b) a log file next to the save data, under
        %APPDATA%\love\pokemon-love2d\
    (c) the F10 mod manager panel.

  CALIBRATION STEP - prove you can see output at all:
    1. Just launch the game. On the mods.loaded event - at boot, before the
       title screen - the mod emits one INFO line reporting its contract
       version, save schema, species manifest version, hash, and PRNG.
       At the time of writing it is prefixed "milestone 14 ready (contract=...".
    2. Confirm you can actually see that line somewhere. No save or New Game
       is required.
    If you cannot find it, you have no working log channel. Any later test
    whose expected result is "no warning appears" is meaningless until you
    fix this - absence of a warning and absence of logging look identical.

  KNOWN GAP: some diagnostics are emitted at DEBUG level, and mod.log:debug is
  not part of the documented API-2 surface. The mod guards those calls, so a
  missing debug method is harmless, but the message is silently dropped. Two
  messages are affected:
    - the auto-seed "best-effort runtime material" notice (SEED-08)
    - the suppressed boot-skeleton save.created notice (SAVE-10)
  If your build has no debug channel, treat those two as NOT OBSERVABLE rather
  than as passes, and verify them by the alternative means given in the tests.

2. THE SAVE EDITOR - YOUR MAIN ACCELERATOR
--------------------------------------------------------------------------------

Close the game first. From the engine repository root:

    love . --editor
    love . --editor --save "%APPDATA%\love\pokemon-love2d\save.lua"

The editor can change: party, boxes, items, event flags, map location / warp
position, and Pokedex flags. Every write makes a timestamped .bak first.

2.1 CRITICAL RULE - do not hand-edit the randomizer namespace

  save.modData.pokemon_randomizer is checksummed. Editing ANY field inside it
  (seed, settings, compatibility, mappings, diagnostics) invalidates the
  checksum and the mod will quarantine the run on load.

  That is a legitimate test (see SAVE-05) but it must be deliberate. If you
  edit it by accident, every later result in that session is garbage.

  Editing anything OUTSIDE that namespace - party, boxes, items, flags,
  position, money, Pokedex - does NOT touch the randomizer checksum. That is
  what makes the editor safe to use as an accelerator.

2.5 The single biggest time-saver

  Make ONE "god save" per configuration:
    all 8 badges, all HMs, all key items, all three fossils, all three rods,
    99999 money, 9999 coins, empty party, empty boxes, and every gate flag set
    but every reward flag CLEAR.

  Copy that file aside. For each encounter test, restore it, warp, test, then
  restore again. This turns a 20-hour playthrough into a 10-minute loop.
  Make a fresh god save per configuration - do not reuse one across configs,
  because the randomizer namespace inside it belongs to that run's seed.


--------------------------------------------------------------------------------
3. READING THE MOD'S OWN OUTPUT
--------------------------------------------------------------------------------

3.1 Options screen header

  Open OPTIONS > RANDOMIZER. The header shows:
    <PAGE NAME> <n>/<total>
    LOCKED:<first 8 of the active seed>   ... a randomized run is active
    ACTIVE:VANILLA                        ... run exists but is not randomized
    ACTIVE:DISABLED                       ... saved state was quarantined
    ACTIVE:NONE                           ... no run loaded
    NEXT NEW GAME                         ... the rows below are next-run only

3.2 Actions page

  REVIEW NEXT RUN ... settings + pool size + validation warnings for the NEXT run
  COPY ACTIVE SEED .. seed, run code, algorithm, and locked category summary
  VIEW SPOILERS ..... in-game spoiler browser for the ACTIVE run
  EXPORT SPOILERS ... writes the plaintext .txt (path shown on screen)
  RESET DEFAULTS .... confirm prompt, restores STANDARD and clears seed text

3.3 Diagnostic codes worth recognising

  These appear in the spoiler log DIAGNOSTICS section and in engine logs.
  Seeing one is not automatically a bug - most are deliberate, recorded
  degradations. Seeing one you cannot explain is a bug.

    WILD_UNIQUENESS_POOL_RESET / TRAINER_UNIQUENESS_POOL_RESET
        one-to-one pool genuinely exhausted; a new pool opened
    WIDEN_STRENGTH / DROP_STRENGTH / DROP_TYPE
        ordered, bounded relaxation of a soft filter
    PROGRESSION_MAP_UNKNOWN
        a map is not in the Red/Blue progression model, so it is excluded
        from catchability guarantees
    TRADE_REACHABILITY_REPAIRED / TRADE_REACHABILITY_UNSATISFIED
        the validator swapped, or could not swap, an unreachable trade request
    TRAINER_SOURCE_UNAVAILABLE / TRAINER_NO_CANDIDATE
        a single trainer slot stayed vanilla
    STARTER_TRIAD_UNAVAILABLE
        no primary-type cycle existed; fell back to RANDOM
    SPECIES_METADATA_CONFLICT_RESOLVED
        two mods described the same species; a deterministic policy won
    COMPATIBILITY_CHANGED / RELEVANT_MODS_CHANGED
        the enabled mod set differs from the New Game snapshot
    SAVE_SIZE_BUDGET_EXCEEDED
        serialized mappings exceeded 256 KiB (262144 bytes)

  These indicate a whole category fell back to vanilla and should be
  investigated whenever they appear on stock data:
    WILD_GENERATION_FAILED, STARTER_GENERATION_FAILED,
    STATIC_GIFT_GENERATION_FAILED, TRADE_PRIZE_GENERATION_FAILED,
    TRAINER_GENERATION_FAILED, CROSS_CATEGORY_VALIDATION_FAILED

  These mean the run is broken and must never appear on stock data:
    GENERATOR_ERROR, INVALID_GENERATION_RESULT, INVALID_RUN_CONFIGURATION,
    RANDOMIZER_SAVE_DISABLED, EMPTY_POOL

OPT-05 [P1] Seed text entry and normalization  - PASSED
  The seed limit is 32 characters. Note there are three separate gates and
  they measure different things - test them separately:
    (a) the naming screen caps RAW keystrokes at 32;
    (b) stored-value validation rejects a stored string longer than 32;
    (c) Seed.normalize reports TOO_LONG on the CANONICAL string, i.e. after
        whitespace is collapsed, the ends are trimmed, and it is uppercased.

  1. SEED TEXT, enter:  "  my   seed  "  (leading/trailing/repeated spaces)
  2. Re-open the row and read the stored value.
  3. Enter "race_seed-01".
  4. Type 32 characters (e.g. "A" thirty-two times), then attempt to type one
     more character - the 33rd.
  5. Enter 32 characters that include repeated internal spaces, for example
     "AAAA    BBBB    CCCC    DDDD  EEE" trimmed to exactly 32 raw characters.
     Save it, then REVIEW NEXT RUN.
  6. Enter punctuation such as "MEW!".
  7. Clear the field to blank with SEED MODE = MANUAL, then REVIEW NEXT RUN.
  EXPECT: step 2 shows MY SEED (uppercased, collapsed, trimmed).
  EXPECT: step 3 stores RACE_SEED-01.
  EXPECT: step 4 - the 33rd keystroke is ignored. The field stays at 32
          characters and the entry screen does not error or close.
  EXPECT: step 5 is ACCEPTED. Collapsing runs of spaces makes the canonical
          seed SHORTER than 32, so this is a valid seed, and REVIEW NEXT RUN
          shows VALIDATION: OK. Record the canonical value - a later run with
          the collapsed form as the seed must produce the same run code
          (cross-check with SEED-02).
  EXPECT: step 6 is rejected on commit, shows INVALID SEED, and leaves the
          previous valid seed unchanged. It must never be stored.
  EXPECT: step 7 shows WARNING INVALID_MANUAL_SEED in REVIEW NEXT RUN.

OPT-05b [P2] Over-long seed from outside the UI
  Gate (c) above cannot be reached through the naming screen: raw input is
  capped at 32 and normalization only ever shrinks a string. Reach it directly.
  1. Close the game. Open %APPDATA%\love\pokemon-love2d\options.lua.
  2. In the pokemon_randomizer block set seed_text to a 40-character string of
     letters with no spaces, e.g. forty "A" characters.
  3. Launch the game, set SEED MODE = MANUAL, and open REVIEW NEXT RUN.

  EXPECT: the stored value is rejected as invalid. Either the row falls back
          to the declared default (blank) and REVIEW NEXT RUN reports
          INVALID_MANUAL_SEED, or the value is shown but flagged. It must not
          be accepted as a usable seed.
  EXPECT: the NEW GAME in step 4 produces a vanilla run with the options
          header reading ACTIVE:VANILLA - never a partially randomized save.
  EXPECT: the game does not crash and options.lua is not corrupted.

OPT-11 [P1] SAME STAGE ignores BST and preserves evolution stage
  1. CFG-I. NEW GAME and export the spoiler log.
  2. Compare at least ten wild mappings, five statics/gifts/prizes, five trade
     sides, and twenty trainer slots with their vanilla source species.
  3. Include at least one very large BST difference if the seed supplies one.
  EXPECT: every randomized source/destination pair has the same derived stage:
          BASIC maps to BASIC, MIDDLE to MIDDLE, and FINAL to FINAL.
  EXPECT: large BST differences are allowed; no percentage band is enforced.
  EXPECT: no WIDEN_STRENGTH or DROP_STRENGTH diagnostic is produced.
  EXPECT: type, legendary, progression, and duplicate rules still apply.
          If they leave no same-stage destination, only that affected slot
          remains vanilla; the stage requirement is never relaxed.

OPT-12 [P1] Absolute BST +/-50 and +/-100
  1. CFG-J with BST +/-50. Export the spoiler log and compare at least fifty
     source/destination pairs across wild, static/gift/prize, trades, and
     trainers.
  EXPECT: each destination's five-stat BST is within 50 points of its source,
          unless a WIDEN_BST or DROP_BST diagnostic records a deterministic
          relaxation. The comparison is absolute, not a percentage.
  2. Repeat with BST +/-100.
  EXPECT: the inclusive range is 100 points. A difference of exactly 100 is
          valid; 101 is invalid unless a relaxation is recorded.
  EXPECT: identical seeds and settings reproduce identical results.

  1. Set SEED MODE = MANUAL, SEED TEXT = PRESET SEED, ENABLE SPOILERS = OFF,

  2. Choose SAVE PRESET, enter FOREST RUN, and confirm.
  3. Confirm PRESET now reads FOREST RUN. Restart the application and confirm
